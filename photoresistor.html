Фоторезистор

Датчик света: чем ярче, тем меньше его сопротивление. Подключим к Arduino Nano, спрячем в коробку и будем закрывать её окошко ширмой.

Датчик в коробке, ширма на окошке

Фоторезистор — это резистор из полупроводника, который «проводит» тем лучше, чем больше на него падает света. У самого ходового GL5528 в темноте не меньше 1 МОм, в сумерках (10 лк) — 10–20 кОм, при комнатном свете (100–300 лк) — 2–5 кОм, на ярком солнце — сотни ом. Подробнее — ниже.

Фоторезистор стоит в коробке, свет попадает только через окошко. Тяните ширму мышкой (или пальцем) или двигайте ползунок — опущенная ширма закрывает окошко целиком, и внутри полная темнота.

ширма поднята окошко закрыто

Закрытое окошко — это настоящая темнота при любом свете снаружи: остаётся только темновое сопротивление, 1 МОм, analogRead ≈ 10. Ползунок ниже — сколько света снаружи кроме солнца (комната, небо); он важен, только пока окошко открыто.

Как подключить к Arduino Nano

Сам по себе фоторезистор не выдаёт напряжение — он только меняет сопротивление. Arduino же умеет измерять напряжение. Поэтому к фоторезистору добавляют обычный постоянный резистор, и получается делитель напряжения — как потенциометр, только «ползунок» двигает свет.

  • Одна нога фоторезистора — на +5V, другая — на пин A1.
  • От A1 же — резистор 10 кОм на GND. У фоторезистора нет полярности, ноги можно не различать.
  • Больше света → меньше сопротивление фоторезистора → напряжение на A1 ближе к 5 В → analogRead больше.
  • Если поменять местами фоторезистор и 10 кОм, всё станет наоборот: больше света — меньше число.

Почему 10 кОм: делитель чувствительнее всего, когда постоянный резистор примерно равен сопротивлению фоторезистора при «рабочем» освещении. Для комнаты подходит 10 кОм, для тёмного помещения — 47–100 кОм, для улицы — 1 кОм.

int light = analogRead(A1);    // 0 — темно, 1023 — очень светло
// в скетче sine_pm_am_crush_lfo2.ino:
amDepth = map(light, LIGHT_MIN, LIGHT_MAX, 0, 255);   // свет → глубина тремоло

Формулы на странице: U = 5 В × 10 кОм / (R + 10 кОм), сопротивление — по даташиту GL5528: R = 15 кОм × (лк / 10)−0.6, в полной темноте 1 МОм. Настоящий датчик может отличаться в 2–3 раза, поэтому LIGHT_MIN в скетче подбирают по факту — или Arduino находит его сам при включении, см. точку темноты.

Какой фоторезистор продают «для Arduino»

В наборах и на AliExpress почти всегда лежат китайские CdS-фоторезисторы серии GL55xx диаметром 5 мм (производитель — Senba, у перепродавцов маркировка бывает LDR5528, 5528 и т. п.). Чаще всего это GL5528; на ленте их не различить, цифры видны только на упаковке. Параметры из даташита серии:

GL552810–20 кОм1 МОм0,6
GL5537-120–30 кОм2 МОм0,6
GL5537-230–50 кОм3 МОм0,7

GL5549100–200 кОм10 МОм0,9
  • Темновое сопротивление по даташиту меряют через 10 секунд после того, как выключили свет 10 лк. CdS «темнеет» медленно: если оставить датчик в темноте на минуты, сопротивление продолжает расти и уходит за несколько мегаом. А на свет он реагирует быстро — 20–30 мс.
  • γ (гамма) показывает, во сколько раз падает сопротивление, когда света становится в 10 раз больше: в 10γ раз. У GL5528 это 100,6 ≈ 4: 15 кОм при 10 лк → около 4 кОм при 100 лк.
  • Выше 100 лк даташит ничего не обещает, значения на солнце — это продолжение той же кривой. Реальный датчик на ярком солнце показывает десятки–сотни ом.
  • Разброс между экземплярами — в 2 раза (это и есть «10–20 кОм»), плюс сопротивление зависит от температуры: на морозе оно на 20% меньше, чем при +20 °C.

Видно главное неудобство: от комнаты до солнца число меняется всего на ~250 единиц, а от темноты до комнаты — на 700. Фоторезистор чувствует свет «логарифмически», как глаз. Если для эффекта важна именно яркая часть, поставьте постоянный резистор поменьше (1–2 кОм).

Если у вас не голый фоторезистор, а модуль на плате (с LM393 и выходами DO/AO), там тот же GL5528 и резистор 10 кОм, но часто включённые наоборот: на AO при свете число уменьшается. Проверьте и при необходимости поставьте в скетче AM_INVERT 1.

Источники: даташит серии GL55 (Senba), даташит GL5528 (Rapid).

Точка темноты: Arduino калибруется сам

Схема как на картинке вверху: фоторезистор в коробке, окошко закрывается ширмой. Включаем Arduino с закрытым окошком — он измеряет свет в коробке (у GL5528 с 10 кОм это ≈ 2–10) и запоминает его как «полностью темно». Потом открываем окошко, и всё, что светлее, растягивается на диапазон от 0 (темно) до 255 (солнце). Так не нужно подбирать LIGHT_MIN вручную: у каждого датчика и каждой коробки своя темнота, а Arduino находит её сам. Попробуйте кнопку «Включить Arduino» под картинкой — она делает то же, что этот код.

Как это устроено:

  • В setup(), до startMozzi(), усредняем 64 обычных analogRead (около 0,3 с). После запуска Mozzi забирает АЦП себе, и читать можно только через mozziAnalogRead.
  • К среднему добавляем небольшой запас DARK_MARGIN, чтобы шум АЦП в темноте не давал «шуршания».
  • Если потом стало ещё темнее, чем при включении (например, включили, когда ширма закрывала окошко не до конца), точка темноты сдвигается вниз сама.

Полный пример: синус 220 Гц на D9, громкость задаёт свет.

// Фоторезистор с «точкой темноты»: при включении Arduino запоминает
// текущий свет как «полностью темно» и дальше считает свет от неё до солнца.
// Схема: +5V — фоторезистор — A1 — 10 кОм — GND. Звук на D9.
#include <Mozzi.h>
#include <Oscil.h>
#include <tables/sin2048_int8.h>

#define LDR_PIN      A1
#define LIGHT_SUN    1000   // analogRead на солнце (GL5528 + 10 кОм: около 975–1020)
#define DARK_MARGIN  8      // запас над точкой темноты, чтобы шум АЦП не «шуршал»
#define CAL_SAMPLES  64     // сколько замеров усреднить при калибровке (64 × 5 мс ≈ 0,3 с)

Oscil<SIN2048_NUM_CELLS, MOZZI_AUDIO_RATE> aSin(SIN2048_DATA);

int darkPoint;              // analogRead, который считаем «полностью темно»
int lightSm;                // сглаженный analogRead × 16
uint8_t level = 0;          // 0 (темно) … 255 (солнце)

// Усредняем несколько замеров — это и есть точка темноты.
// Вызывать ДО startMozzi(): обычный analogRead работает только до него.
int calibrateDark(uint8_t pin) {
  analogRead(pin);                       // первый замер после смены пина выбрасываем
  long sum = 0;
  for (int i = 0; i < CAL_SAMPLES; i++) {
    sum += analogRead(pin);
    delay(5);
  }
  int dark = sum / CAL_SAMPLES + DARK_MARGIN;
  return min(dark, LIGHT_SUN - 100);     // включили на солнце — оставим хоть какой-то диапазон
}

void setup() {
  darkPoint = calibrateDark(LDR_PIN);
  lightSm = darkPoint << 4;
  aSin.setFreq(220);
  startMozzi();
}

void updateControl() {
  int raw = mozziAnalogRead(LDR_PIN);
  lightSm += ((raw << 4) - lightSm) >> 3;        // сглаживание, как в скетче курса
  int light = lightSm >> 4;

  // стало темнее, чем при включении? сдвигаем точку темноты вниз
  if (light + DARK_MARGIN < darkPoint) darkPoint = light + DARK_MARGIN;

  light = constrain(light, darkPoint, LIGHT_SUN);
  level = map(light, darkPoint, LIGHT_SUN, 0, 255);
}

AudioOutput updateAudio() {
  return MonoOutput::from16Bit(aSin.next() * level);   // громкость = свет
}

void loop() {
  audioHook();
}

То же самое в скетче курса sine_pm_am_crush_lfo2.ino — две правки:

// 1) вместо  #define LIGHT_MIN 147
int LIGHT_MIN = 147;             // теперь переменная: в setup() станет точкой темноты
#define DARK_MARGIN    8

// 2) в setup() вместо строки  lightSm = analogRead(LIGHT_PIN) << 4;
  analogRead(LIGHT_PIN);
  long sum = 0;
  for (int i = 0; i < 64; i++) { sum += analogRead(LIGHT_PIN); delay(5); }
  LIGHT_MIN = min(sum / 64 + DARK_MARGIN, LIGHT_MAX - 100);
  lightSm  = LIGHT_MIN << 4;

Остальной код не меняется: constrain и map работают и с переменной. Оба варианта проверены компиляцией для Arduino Nano с Mozzi 2.0.4. Важно: включайте Arduino (или жмите Reset) при закрытом окошке. Если включить с открытым, «темнотой» станет текущий свет, и эффект начнётся только от ещё более яркого.
